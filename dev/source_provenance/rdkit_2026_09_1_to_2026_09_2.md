## Numerical boundary that must be resolved early

`Graphs.py` in the target tag uses NumPy eigenvalue routines; the later C++
descriptor port #9754 and exact-integer IPC #9884 are not this release's
default implementation. `RdkitCompatible` must follow 2026.09.2 when the pin
changes. The explicitly selectable `ExactPolynomial` remains separately
source-pinned; its outstanding bulk/performance validation is not completed
by upgrading the default.

Current BCUT code implements an Eigen path, not the NumPy/LAPACK path. Neither
Eigen nor exact integer coefficients can silently substitute for the target
default. Audit the actual target wheel's symmetric/general drivers, arithmetic,
root ordering (including equal magnitudes), complex convolution, rounding and
error paths. Existing asymmetric matrix support remains supported. Record any
missing numerical backend or ownership decision before implementing a shared
solution; preserve bit-exact non-NaN acceptance and the approved NaN rule.

## Evidence and acceptance

Implementation starts from the source inventory and all reachable changed
branches. Port source-backed performance changes along with semantic fixes.
Each independent changed behavior receives a small owner regression; existing
runtime/type/binding guarantees are inherited, not retested per API.

Only after the source-led port and owner regressions are complete: prepare
version-isolated references using the released RDKit **2026.9.2 Python wheel**,
then run the existing Cargo corpus/special comparisons, followed by complete
5k and frozen million-record selections. Preserve old references and failed
reports. Source-backed fixes after comparison require first-divergence
instrumentation, not molecule-specific branches, constants or tolerance changes.
Record full runs, affected replays, matching errors, mismatches, crashes,
timeouts and unfinished work separately. Python/JS protocol checks and native
parity do not establish WASM numerical parity.

## Accepted static audit — 2026-11-28

Three subagents inspected chemistry (41 paths/108 hunks), geometry
(41/145), and IO/descriptors (55/146). The main agent inspected integration
(108/374), checked exact file/hunk coverage, compared critical findings against
both source and CK, and accepted the corrected receipts. Total: **245 paths,
773 textual hunks, four binary PNG additions**. The 72-commit index was checked
against the endpoint source diff; the ledger below covers that diff, not 72
separate intermediate checkouts.

There are **18 independent required ports**, plus a reaction caller that inherits
the shared SMARTS port. These are upgrade differences, not claims that CK is
incorrect against its current 2026.09.1 target. In particular, several existing
comments deliberately preserve baseline behavior that the new release fixes.
No implementation, tests, benchmarks, corpus comparisons, reference generation,
pin/environment changes or Git operations were performed in this audit.
Static cost conclusions are code inspection, not measured speedups.

The main acceptance corrected one receipt: the new P/S 12-point wedge rendering
case reaches an existing, unchanged MolFileStereochem/preparation caller. There
is no MolFileStereochem source change in this diff and no additional new wedge
selection dependency for that case. The separate bridged-ring selection change
